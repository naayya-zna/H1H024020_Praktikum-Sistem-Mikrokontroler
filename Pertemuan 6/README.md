PERTANYAAN PERCOBAAN 6A
1. Proses interrupt mengubah kondisi LED: Ketika tombol ditekan, sinyal pada pin 2 mengalami transisi dari HIGH ke LOW (FALLING edge) karena pin dikonfigurasi dengan INPUT_PULLUP. Transisi ini memicu interrupt INT0, yang menyebabkan mikrokontroler menghentikan sementara eksekusi loop() dan langsung menjalankan fungsi tombolInterrupt(). ISR tersebut melakukan toggle pada variabel ledState. Setelah ISR selesai, loop() dilanjutkan dan digitalWrite() pada iterasi berikutnya menuliskan nilai ledState terbaru ke LED.
2. Fungsi attachInterrupt(): Fungsi ini mendaftarkan hubungan antara pin interrupt fisik dengan fungsi ISR yang akan dipanggil, serta menentukan kondisi sinyal pemicunya (mode). Tanpa fungsi ini, mikrokontroler tidak mengetahui ISR mana yang harus dieksekusi saat interrupt terjadi.
3. Alasan delay() dan Serial.print() dilarang dalam ISR: Fungsi delay() bergantung pada interrupt Timer0 yang sedang terblokir selama ISR berjalan, sehingga akan menyebabkan deadlock. Serial.print() menggunakan buffer berbasis interrupt UART yang juga tidak dapat diproses. Keduanya dapat menyebabkan sistem hang atau berperilaku tidak terduga.
4. Fungsi keyword volatile: Keyword volatile memberitahu compiler bahwa nilai variabel ledState dapat berubah di luar alur normal program (yaitu di dalam ISR). Tanpa volatile, compiler dapat menyimpan nilai variabel dalam register CPU dan tidak membaca ulang dari memori, sehingga perubahan yang dilakukan ISR tidak terlihat oleh loop() utama.
5. Perbedaan mode interrupt: Mode RISING memicu interrupt saat sinyal berubah dari LOW ke HIGH (tombol dilepas pada konfigurasi pull-up). Mode FALLING memicu saat sinyal berubah dari HIGH ke LOW (tombol ditekan). Mode CHANGE memicu pada setiap perubahan sinyal, baik naik maupun turun, sehingga satu penekanan tombol memicu dua kali interrupt. Mode LOW terus memicu selama pin berada pada kondisi LOW, berpotensi menyebabkan ISR dipanggil berulang kali selama tombol ditahan. Pada percobaan, mode FALLING paling tepat digunakan karena hanya merespons saat tombol pertama kali ditekan.
   
PERTANYAAN PERCOBAAN 6B
1. Cara kerja millis() pada program: Setiap iterasi loop(), program membaca nilai millis() ke variabel currentMillis. Nilai ini dibandingkan dengan previousMillis yang menyimpan waktu terakhir LED berubah. Jika selisih keduanya sudah mencapai atau melampaui 1000 ms, LED di-toggle dan previousMillis diperbarui dengan nilai currentMillis terkini. Proses ini berulang terus-menerus tanpa memblokir eksekusi.
2. Perbedaan delay() dan millis(): delay(n) menghentikan seluruh eksekusi program selama n milidetik, sementara millis() hanya membaca nilai timer tanpa menghentikan apapun. Dengan delay(), tidak ada kode lain yang dapat berjalan selama periode tunggu. Dengan millis(), program terus berjalan dan hanya mengeksekusi aksi tertentu ketika interval telah terpenuhi.
3. Alasan millis() disebut non-blocking: Karena fungsi ini tidak menghentikan eksekusi program. Program terus berjalan melalui loop() dengan normal; kondisi waktu hanya dicek, bukan ditunggu. Akibatnya, tugas-tugas lain dalam loop() tetap dieksekusi pada setiap iterasi.
4. Modifikasi dua LED berbeda interval: Untuk menjalankan dua LED dengan interval berbeda (LED1 = 1000 ms, LED2 = 500 ms), digunakan dua set variabel previousMillis secara terpisah (previousMillis1 dan previousMillis2) dengan interval masing-masing. Pada setiap iterasi loop(), kedua kondisi diperiksa secara independen. LED1 berubah setiap 1000 ms dan LED2 setiap 500 ms tanpa saling mengganggu, mendemonstrasikan konsep multitasking sederhana berbasis millis().
  
JAWABAN PERTANYAAN PRAKTIKUM
1. Keuntungan interrupt dibanding polling: Interrupt jauh lebih efisien dalam penggunaan CPU karena mikrokontroler hanya merespons ketika kejadian benar-benar terjadi, bukan terus-menerus memeriksa kondisi. Respons interrupt juga lebih cepat karena penanganan langsung terpicu oleh hardware, sementara polling bergantung pada frekuensi pengecekan dalam loop. Selain itu, interrupt membebaskan CPU untuk menjalankan tugas lain di antara kejadian [1][3].
2. Pentingnya timer dalam sistem embedded dan real-time: Timer menyediakan referensi waktu yang akurat dan independen dari beban kerja CPU. Pada sistem real-time, ketepatan timing sangat kritis untuk kendali motor, komunikasi serial, pembangkitan PWM, dan penjadwalan tugas. Timer memungkinkan sistem melakukan pengukuran waktu, menghasilkan sinyal periodik, dan menerapkan deadline eksekusi tanpa overhead polling yang boros [2][5].
3. Alur kerja sistem dengan interrupt dan timer digabung: Program utama berjalan normal dalam loop(). Timer secara periodik menghasilkan interrupt untuk menjalankan tugas terjadwal seperti pembacaan sensor atau pembaruan tampilan. Secara bersamaan, external interrupt dapat terpicu kapan saja oleh kejadian eksternal seperti penekanan tombol. Kedua jenis interrupt memiliki prioritas yang dapat dikonfigurasi; setelah masing-masing ISR selesai, kontrol dikembalikan ke titik eksekusi sebelumnya. Hasilnya adalah sistem yang responsif terhadap event eksternal sekaligus menjaga ketepatan timing periodik [1][2].
4. Dampak ISR yang terlalu panjang atau kompleks: ISR yang panjang menyebabkan program utama tertangguhkan dalam waktu lama, meningkatkan latency respons sistem. Interrupt lain yang terjadi saat ISR berjalan dapat terlewat atau tertunda. Jika menggunakan fungsi yang bergantung pada interrupt lain (seperti delay() atau Serial.print()), sistem dapat mengalami deadlock atau hang. Pada sistem real-time, ISR panjang dapat menyebabkan kegagalan deadline yang berdampak pada keselamatan sistem [1][4].
